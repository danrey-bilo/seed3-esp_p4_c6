# p4_audio_dashboard

Изолированный компонент интерфейса дисплея 1024×600 и GT911:

- страницы `MONITOR`, `PEDALBOARD` и `SETTINGS`;
- четыре индикатора уровня и CPU Seed3;
- единая частота из `audio_dashboard_status_t.sample_rate`;
- неблокирующая очередь команд частоты, `ON/BYPASS`, масок каналов и
  автоматического выбора окна, а также профиля SPI;
- меню окон, открываемое только свайпом сверху вниз.

Короткое нажатие в верхней области ничего не открывает. Постоянной подсказки
`SWIPE DOWN` на экране нет. GUI работает в низкоприоритетной задаче и получает
только атомарные снимки; LVGL не вызывается из USB/SPI ISR.

Переключатели `IN1/IN2` и `OUT1/OUT2` управляют реальными масками тракта.
Команда схлопывается до последнего состояния, а подтверждённый снимок control
слоя повторно синхронизирует цвет и положение переключателей.

При включённой настройке `AUTO WINDOW SWITCH` отсутствие ПК выбирает
`PEDALBOARD`, а появление реальных USB SOF выбирает `MONITOR`. Настройка
сохраняется слоем `p4_audio_control` в NVS. Ручной выбор через меню остаётся
доступным и не перезаписывается до следующего фактического изменения USB.
Панель `ON/BYPASS` скрыта в LOCAL, где педалборд принудительно включён и выбора
нет; с владельцем WINDOWS панель снова появляется.

В `SETTINGS` доступен профиль `BALANCED/LOW LATENCY`. Строка `ACTIVE` может
показывать `LOCAL`: это автоматический control-only режим при закрытых USB
endpoint, а не третий сохраняемый пользовательский профиль.

Публичный API — [audio_dashboard.h](include/audio_dashboard.h).
