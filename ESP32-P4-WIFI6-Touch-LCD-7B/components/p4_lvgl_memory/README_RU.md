# Память интерфейса ESP32-P4

Небольшой backend `LV_STDLIB_CUSTOM` для LVGL 9.5: все объекты, стили,
дескрипторы рисования и прочие выделения через `lv_malloc`/`lv_realloc`
получают память с `MALLOC_CAP_SPIRAM | MALLOC_CAP_8BIT`.

Внутренняя SRAM нужна USB/SPI DMA и FreeRTOS. Нельзя расходовать её
пропорционально числу отображаемых педалей. Если PSRAM закончилась,
аллокатор возвращает NULL, а не переключается на внутреннюю память.
Это не песочница и не механизм защиты от произвольного исчерпания PSRAM.

Подключение: `REQUIRES p4_lvgl_memory` в компоненте интерфейса. Компонент
использует `WHOLE_ARCHIVE`, поскольку точки входа вызываются самой LVGL,
которая находится в другой статической библиотеке.

Настройки ESP-IDF:

```ini
CONFIG_LV_USE_CUSTOM_MALLOC=y
# CONFIG_LV_USE_CLIB_MALLOC is not set
CONFIG_SPIRAM_MALLOC_RESERVE_INTERNAL=65536
```

`lv_mem_monitor()` показывает весь общий PSRAM heap, включая других
потребителей; это не персональная статистика LVGL. `lv_mem_test()` проверяет
целостность PSRAM heap. Аллокатор используется в задачах, не из USB/audio ISR.

Стеки задач и аппаратные буферы дисплея продолжают выделяться BSP/FreeRTOS
с их собственными требованиями. Этот компонент не меняет SPI-протокол,
USB-дескрипторы и алгоритмы обработки звука.
