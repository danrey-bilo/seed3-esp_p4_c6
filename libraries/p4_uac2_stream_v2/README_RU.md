# p4_uac2_stream v0.2 — 2×2, PCM16/24, 44,1–96 кГц

Переносимый USB Audio Class 2 transport для ESP-IDF 5.5.5 и ESP32-P4 rev1.x.
Это USB-компонент, не SPI-драйвер, не ASIO-драйвер и не ресемплер.
Seed3 остаётся источником аудиочасов. Прежний проверенный fixed-48k снимок
`libraries/p4_uac2_stream` v0.1 сохранён отдельно и не изменён.

**Проверены 60 s capture, 100 open/close и 301 s duplex 96k с WASAPI 10 ms.
Минимум Windows 3 ms доступен, но длинный тест на этом ПК не прошёл.
Результаты и границы проверки — в [отчёте](docs/TEST_REPORT_RU.md).**

## Профиль

| Параметр | Значение |
|---|---|
| USB / Windows | High Speed, штатный `usbaudio2.sys` |
| Каналы | 2 capture + 2 playback одновременно |
| Частоты | 44 100 / 48 000 / 88 200 / 96 000 Гц |
| USB alt 1 | signed PCM16, 2-байтный little-endian subslot |
| USB alt 2 | signed PCM24, 4-байтный subslot, младшие 8 бит = 0 |
| API приложения | interleaved `int32_t`, PCM24 left-aligned для обоих USB форматов |
| HS интервал | bInterval=3, один пакет каждые 0,5 мс |
| Размер пакета | до 49 stereo frames: 196 / 392 байта |
| Playback | asynchronous OUT + explicit feedback IN |
| DMA | internal SRAM, 64-byte alignment, линейные слоты |
| Identity | VID 303A, PID 40A4, serial SEED3P4SPI2; bcdDevice 0200 |

В обоих направлениях одна физическая частота. Закройте оба потока перед
сменой частоты; переключение разрядности не меняет аудиочасы.
32-битный контейнер **не добавляет** точности к 24-битному источнику.

192 кГц не объявляется: эксперимент при SPI 20 MHz показал около 4300
транзакций/с вместо необходимых 6000. Полный цикл READY/DMA/обработки,
а не USB, ограничивает этот вариант. Для 96 кГц требуется 3000 транзакций/с,
6,912 Mbit/s (34,56% проводного времени на 20 MHz) плюс межпакетные паузы.
USB HS сам по себе не является этим ограничением. Дескрипторы Full Speed
ограничены 44,1/48 кГц; отдельная FS-квалификация не выполнена.

## Подключение

Скопируйте эту папку как `components/p4_uac2_stream` в свой ESP-IDF проект.
Не подключайте одновременно старый UAC-компонент или ещё одного владельца
TinyUSB/DWC2. Пример интеграции и ограничения приведены в
[INTEGRATION_RU.md](docs/INTEGRATION_RU.md), контракт — в
[API_RU.md](docs/API_RU.md).

```c
ESP_ERROR_CHECK(p4_uac2_init());

// В SPI task: передать это значение Seed3 как запрос частоты.
uint32_t wanted = p4_uac2_requested_rate();

// После проверки принятого SPI header/CRC, для каждого реального блока:
p4_uac2_source_rate(actual_seed_rate, new_seed_session);
p4_uac2_capture_write(capture_pcm24, frames);
p4_uac2_playback_read(playback_pcm24, frames);
```

`actual_seed_rate` — подтверждённая Seed частота, а не просто копия запроса.
При отсутствии источника библиотека не генерирует фиктивный аудиоклок.
Переход между частотами отделяется новой сессией и сбрасывает старые tails.

## Минимальная задержка

Два разных буфера нельзя путать:

1. Буфер приложения Windows выбирается через WASAPI exclusive или настройки
   DAW. `GetDevicePeriod` на проверяемом ПК сообщает минимум 3 мс. При 48 кГц
   это 144 frames, при 96 кГц — 288 frames. Для 44,1/88,2k тестер округляет
   вверх до 133/265 кадров. Минимум драйвера не гарантирует устойчивости
   на загруженном ПК: см. результаты разных периодов в отчёте.
   На этом ПК рекомендуемый проверенный период — **10 мс**; на 3 мс
   в длинной записи обнаружен пропуск 6 мс на стороне хостового потока.
   Драйвер может потребовать дополнительное выравнивание;
   тестер повторно согласовывает его и выводит фактическое значение.
2. Запас устройства задаётся `p4_uac2_set_buffer_ms(1|2|4)`, только с закрытыми
   потоками. Начальное значение — 1 мс, округлённое вверх до блока 32 frames,
   минимум два блока. Это 64 frames для 44,1/48 и 96 для 88,2/96 кГц.

Предельная ёмкость rings 512 frames не означает, что всегда добавляется
задержка 512 frames. Capture регулирует запас вокруг prefill + одного пакета;
готовит не более двух пакетов вперёд. Не обещается измеренная сквозная
задержка 3 мс: к буферу Windows добавляются кодек, SPI, USB и запас устройства.

В Windows формат выбирается в свойствах устройства → «Дополнительно»;
для full-duplex задайте одинаковую частоту входа и выхода. В exclusive-режиме
её задаёт само приложение. Общесистемного ползунка ASIO эта библиотека не создаёт.

## Устойчивость

SPSC rings с фиксированным размером, completion-driven DMA rearm, SOF-планирование,
prefill реальными frames, повтор ISO IN после incomplete, восстановление OUT,
watchdog отсутствия completion, alt 0/1/2, pause/resume и controller recovery.
Активный capture не отправляет zero-length packet. При нехватке PCM отправляет
полный пакет тишины и увеличивает отдельный счётчик — это не успешная запись.

В USB ISR нет PCM-конверсии, malloc, mutex, печати и callback приложения.
Конверсия PCM16/24 и volume/mute выполняются в USB task, SPI работает отдельно.
Фракционный packetizer сохраняет остаток 44,1/88,2 кГц; добавляет/убирает один
frame в длине USB-пакета по заполнению ring, не дублируя и не удаляя PCM samples.

Вместе с этим компонентом требуется новая прошивка Seed3 с переключением PLL3,
программным восстановлением SPI и обработкой новой сессии. Одна замена USB
дескрипторов при старой fixed-48k прошивке Seed недостаточна.

Версии зависимостей и лицензии: [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md).
Проверка экспортированного снимка: `python tests/verify_package.py`.

`examples/compile_check` — независимый compile/link пример без SPI; его не
нужно прошивать вместо основного приложения. Для офлайн-сборки можно передать
`-DP4_UAC2_LOCAL_TINYUSB_DIR=путь/к/espressif__tinyusb` и
`IDF_COMPONENT_MANAGER=0` в окружении. Используется только зафиксированная версия.
