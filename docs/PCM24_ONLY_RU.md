# PCM24-only: Seed3 + ESP32-P4, v0.2.1

Активный проект на 18.09.2026: **2 входа + 2 выхода**, только signed PCM24,
**44 100 / 48 000 / 88 200 / 96 000 Гц**. Под «41 кГц» принято ранее
согласованное значение 44,1 кГц. Нестандартные 41 000 Гц и 192 кГц не объявлены.

## Представление данных и часы

| Участок | Представление |
| --- | --- |
| USB HS, Windows | PCM24 little-endian: 3 байта на отсчёт, 6 на стереокадр |
| SPI и API компонента | `int32_t`, PCM24 left-aligned, младший байт нулевой |
| Seed capture | АЦП L/R, `kUseTestTones = false` |

Упаковка USB не округляет и не отбрасывает значащие биты: например,
`0x12345600` внутри API → `56 34 12` на USB. Значения отрицательные, включая
полную отрицательную шкалу, проходят self-test. Полезная нагрузка USB меньше
на 25%, чем у PCM24-in-32; частота и layout проверенной SPI-шины не изменены.

ПК задаёт частоту стандартным UAC2 Clock Source `SET_CUR`. P4 передаёт её
существующим полем SPI, Seed перестраивает аудиочасы и подтверждает реальную
частоту в ответных пакетах. P4 ждёт подтверждения и prefill. АЦП/DAC Seed —
источник аудиочасов, программного ресемплинга в прошивке нет.

USB: HS `bInterval=3` (0,5 мс), максимум 49 кадров × 6 = 294 байта.
DMA-буферы в internal SRAM, alignment 64, stride 320 байт. USB task упаковывает
capture и распаковывает playback; ISR не делает PCM conversion. Сохранены
SPSC rings, completion-driven rearm, watchdog и explicit feedback для OUT.
Alt 0 закрывает поток; единственный рабочий alt 1 — PCM24. PCM16/alt 2 удалены.
VID/PID/serial сохранены: `303A:40A4`, `SEED3P4SPI2`; `bcdDevice=0x0201`
обозначает изменившийся набор форматов.

Дополнительно исправлена гонка watchdog: время теперь читается **внутри**
короткой критической секции USB. Раньше ISR мог записать новый tick completion
после чтения старого `now`; вычитание unsigned давало почти 2^32 и ложный
timeout здорового endpoint. Первый 301-секундный прогон дал точные 28 896 000
кадров и нулевые ошибки хоста, но выявил прирост recovery на 4,
поэтому он не принят как квалификация. После исправления отдельный длительный
повтор прошёл без прироста recovery; snapshot v0.2 не менялся.

## Как выбрать частоту на ПК

1. Закройте запись и воспроизведение в приложениях.
2. Откройте `mmsys.cpl` → «Запись» → «Микрофон (usb uac)» →
   «Свойства» → «Дополнительно». Выберите 2 канала, 24 бит и нужную частоту.
3. Для «Воспроизведение» → «Динамики (usb uac)» выберите **ту же частоту**.
4. В WASAPI exclusive/DAW частоту задаёт само приложение; выбирайте устройство
   `usb uac` и 24-битный packed PCM. Для shared mode Windows может преобразовать
   формат приложения в установленный формат устройства.

У входа и выхода одни физические часы. Менять частоту при работающем другом
направлении нельзя — остановите **оба**. Несовместимый запрос отклоняется,
а не молча меняет частоту второго потока. При обновлении прошивки один раз
переподключите аудио-USB J1, если Windows сохранила старые параметры.
Название может иметь префикс «3-» — это экземпляр устройства Windows.

## Буферы и восстановление

WASAPI exclusive на проверенном ПК сообщает минимум 3 мс:

| Частота | Минимальное целое число кадров | Период |
| --- | ---: | ---: |
| 44,1 кГц | 133 | 3,016 мс |
| 48 кГц | 144 | 3,000 мс |
| 88,2 кГц | 265 | 3,005 мс |
| 96 кГц | 288 | 3,000 мс |

Это буфер Windows, **не** измеренная сквозная задержка ADC→DAC.
Начните с 10 мс для длительной работы; минимальный буфер зависит от нагрузки
ПК. На прежней v0.2 длинный тест 3 мс имел пропуск, поэтому короткий тест новой
версии не является гарантией устойчивости 3 мс на любом ПК.

Запас устройства отдельно: `buffer 1|2|4` через COM6, только при закрытых
потоках. По умолчанию 1 мс, округляется к 32 кадрам с минимумом 64 кадра.
После reset P4 значение снова 1 мс. SPI работает на 20 МГц.

Seed автоматически возвращается к SPI после перезапуска P4/тайм-аута.
`seed boot` переводит работающий Seed в ROM DFU без кнопок, если подключены
его USB и UART к P4. После прошивки `flash.cmd` запускает Seed автоматически.
Если приложение или провода неисправны, BOOT+RESET остаётся аварийным способом.
Непрерывность звука во время отключения питания/проводов не обещается.

## Сборка, образы и проверка

[Пошаговая прошивка обеих плат](../FLASHING_RU.md). Образы:

- `Seed3/firmware/Seed3P4SpiAudio.bin` — ADC, адрес 0x08000000, DFU 0483:df11.
- `ESP32-P4-WIFI6-Touch-LCD-7B/firmware/ESP32P4_Seed3_SPI_UAC2_2x2_Merged.bin`
  — P4 rev1.x, адрес 0x2000, ESP-IDF 5.5.5; без `esptool --force`.

SHA256 лежат рядом с образами. Снимки `libraries/p4_uac2_stream` и
`libraries/p4_uac2_stream_v2` сохранены без изменений. Активный компонент v0.2.1
отличается от v0.2 дескрипторами и упаковкой USB; API остаётся `int32_t`.

Повторяемые тесты из корня репозитория (GUID берите у текущего устройства):

```powershell
dotnet build tools/WasapiCapture/WasapiCapture.csproj -c Release
$captureId = '168B4F11-B679-48BE-9C6C-1A4DDAB98305'
$renderId = '89632D64-5CC6-481E-AD15-613CC7758118'
$audioPython = 'C:\Espressif\python_env\idf5.5_py3.11_env\Scripts\python.exe'

.\tools\WasapiCapture\bin\Release\net10.0-windows\WasapiCapture.exe --probe-24-only $captureId $renderId --packed24
& $audioPython tools/run_multirate_matrix.py $captureId $renderId --packed24 --adc --period min --output tools/test-output/v2-packed24-matrix-repeat
& $audioPython tools/run_uac2_acceptance.py $captureId --render $renderId --rate 96000 --bits 24 --packed24 --adc --period 10 --output tools/test-output/v2-packed24-repeat
```

`--packed24` задаёт 3-байтовый формат WASAPI. `--adc` проверяет WAV layout/count
и ошибки хоста, **не** RMS/разделение/фазу неизвестного аналогового входа.
Без `--adc` тесты ожидают диагностические синусы 997/1501 Гц из Seed и должны
провалиться на произвольном сигнале АЦП. Перед тестом перепрошивать Seed в режим
синусов не требуется. Длительный тест включает воспроизведение 401/601 Гц
с невысокой амплитудой на аналоговом выходе — уменьшите громкость усилителя.

Параллельно в другом терминале можно записать счётчики:

```powershell
& $audioPython tools/audio_control.py --seconds 420 --output tools/test-output/v2-packed24-repeat-uart.log
```

Не запускайте второй serial monitor и `seed stats` во время этого наблюдения.

## Результат текущей проверки

Обе новые прошивки собраны и записаны в платы. Windows подключил штатный
драйвер без Code 10: 2 IN + 2 OUT, HS. Seed по UART подтвердил `CAPTURE_ADC`.

- 17 offline regression tests — PASS, включая signed PCM24, границы и порчу.
- Живое переключение масок `3/3 → 1/1 → 0/0 → 3/3` — PASS; при 48 кГц
  CPU Seed3 изменяется примерно `13% → 11% → 10% → 13%`, ошибок SPI/CRC/
  sequence не добавляется.
- WASAPI probe: все четыре частоты PCM24 packed доступны в обоих направлениях;
  все восемь проверок PCM16 корректно отклонены как unsupported format.
- 8 duplex-проверок по 12 с (4 частоты × minimum/10 мс): точное число кадров,
  WAV 24/24, blockAlign=6; host discontinuity/timestamp/position/silent flags = 0.
- 100 capture open/close по 0,1 с с последовательным переключением всех
  четырёх частот: PASS, без зависания.
- После исправления watchdog повторены 10 capture/duplex запусков с переходом
  48 → 44,1 → 96 → 88,2 → 48 кГц, minimum buffer, по 2 с: PASS.
- После исправления watchdog: ещё 100 capture open/close на 96 кГц — PASS.
- Финальный 301-секундный duplex на 96 кГц/10 мс — PASS по проверкам транспорта:
  ровно **28 896 000 кадров**, 173 376 000 байт PCM24, WAV 24/24, blockAlign=6.
  Host discontinuity/timestamp/position/silent flags = 0. Во время непрерывного
  потока прирост capture silence/overflow, playback underrun/overflow,
  bad packets, capture/feedback incomplete, recovery и controller restart = 0.
  Максимальный наблюдавшийся интервал завершений capture/playback — 500 мкс.

[Компактный отчёт с числами и хешами](../tools/test-output/qualification-pcm24/summary.json).
Оценка нагрузки P4 при duplex 96 кГц: медиана core0 19,6%, core1 27,3%.
Seed после закрытия USB-потоков, при продолжающемся ADC/SPI 96 кГц: busy 23,5%,
audio callback 5,1%, capture overruns/SPI start errors = 0. Это разные режимы
измерения и оценки по счётчикам планировщика/idle, не точный профайлер ISR.

Ненулевые накопительные incomplete/recovery/overflow при открытии/закрытии
нужно отличать от прироста внутри непрерывного прогона. В матрице два соседних
теста одной частоты могут сливаться в один сегмент UART-анализатора; такой
сегмент включает закрытие/открытие и не доказывает steady-state сбой.
После перепрошивки/перезапуска P4 при продолжающем работать Seed был отброшен
один пакет с неверным SPI-заголовком **до теста**. Абсолютный счётчик `h=1`
сохранён, CRC/sequence=0. Для прогона отдельно проверяется отсутствие прироста
всех SPI-ошибок; старый ненулевой header counter не выдается за абсолютный ноль.

Аналоговые SNR, THD, разделение каналов и сквозная задержка не измерены:
для этого нужен известный сигнал на входе АЦП и измерительная петля.
Предыдущие результаты с синусами v0.2 не перенесены на АЦП как новый PASS.
