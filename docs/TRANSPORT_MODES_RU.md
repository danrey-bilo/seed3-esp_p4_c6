# Режимы транспорта Seed3 ↔ ESP32-P4

Аудиотранспорт имеет три режима. Профиль выбирается на странице `SETTINGS`
экрана P4; `BALANCED` используется по умолчанию. Выбор сохраняется в NVS.
`LOCAL` включается автоматически, когда оба USB audio endpoint закрыты, и не
является отдельной пользовательской настройкой.

| Режим | 44,1/48 кГц | 88,2/96 кГц | Назначение |
| :--- | :---: | :---: | :--- |
| `BALANCED` | 32 frames | 64 frames | Основной: меньше SPI-транзакций и загрузка CPU на высоких частотах |
| `LOW LATENCY` | 32 frames | 32 frames | Минимальный транспортный блок, больше загрузка CPU |
| `LOCAL` | аудио не передаётся | аудио не передаётся | Локальный граф Seed3; по SPI идёт только телеметрия и управление |

DSP callback Seed3 всегда обрабатывает 32 кадра. В `BALANCED` на 88,2/96 кГц
два готовых блока объединяются в одну SPI-транзакцию; размер DSP-блока и
алгоритмы эффектов не меняются. В `LOW LATENCY` каждый блок отправляется
сразу. В `LOCAL` АЦП, ЦАП и локальный граф продолжают работать, но capture и
playback rings не копируются, CRC аудиоданных не вычисляется 1378–3000 раз/с,
а управляющий кадр передаётся примерно раз в 20 мс.

## Протокол

Версия wire protocol — **2**. Физический DMA-кадр фиксирован и равен 544
байтам: заголовок 32 байта и место для 64 стереокадров PCM24-left-aligned в
`int32_t`. Поле `header.frames` равно 32 или 64, `payload_bytes` — 256 или 512;
CRC охватывает заголовок и только действительную часть PCM. Фиксированный
размер DMA позволяет менять профиль без рассинхронизации master/slave.

`LOCAL` обозначается `SPI_AUDIO_FLAG_CONTROL_ONLY`, а `LOW LATENCY` —
`SPI_AUDIO_FLAG_LOW_LATENCY`. При любом переходе Seed3 очищает транспортные
кольца и помечает первый новый кадр `SESSION_START`, поэтому старый PCM не
попадает в новую эпоху.

## Задержка и нагрузка линии

SPI работает в mode 0 на 20 МГц. Один физический кадр занимает 217,6 мкс.

| Частота | `BALANCED`, транзакций/с | `LOW LATENCY`, транзакций/с | Занято линии |
| :--- | ---: | ---: | :--- |
| 44,1 кГц | 1378,125 | 1378,125 | 30,0% |
| 48 кГц | 1500 | 1500 | 32,64% |
| 88,2 кГц | 1378,125 | 2756,25 | 30,0% / 60,0% |
| 96 кГц | 1500 | 3000 | 32,64% / 65,28% |
| `LOCAL` | около 50 | около 50 | около 1,09% |

Размер транспортного блока на 96 кГц — около 0,667 мс в `BALANCED` и
0,333 мс в `LOW LATENCY`. Это только этап Seed↔P4, не полная аналоговая или
WASAPI round-trip latency.

## Стендовая проверка

На реальных платах при 96 кГц, 2×2, PCM24 и full-duplex оба потоковых режима
прошли короткий WASAPI exclusive прогон. Дополнительно основной `BALANCED`
прошёл обязательный 5-минутный тест: ровно **28 800 000 кадров** за 300,293 с,
без discontinuity, silent packet, timestamp/position errors. За устойчивый
участок 293,258 с не вырос ни один счётчик silence, overrun/underrun,
incomplete, endpoint recovery, controller reset или feedback incomplete;
максимальный интервал USB completion составил 0,5 мс. SPI transfer, header,
CRC, sequence и format errors за весь журнал остались нулевыми.

Оценка загрузки в этом тесте:

| Режим | Seed3 | SPI task / core P4 |
| :--- | ---: | ---: |
| `BALANCED`, 96 кГц | около 23% | около 19% |
| `LOW LATENCY`, 96 кГц | около 26% | около 31% |
| `LOCAL`, 48 кГц | около 3% | около 0,5% |

Значения зависят от активного DSP-графа и задач интерфейса. Главный вывод:
`BALANCED` существенно экономит P4 и немного Seed3 на 88,2/96 кГц, а `LOCAL`
освобождает почти всю стоимость межплатной передачи для эффектов.

## Управление и диагностика

Через экран: `SETTINGS → SPI TRANSPORT PROFILE → BALANCED / LOW LATENCY`.

Через COM-порт P4:

```powershell
python .\tools\audio_control.py --port COM6 --command "transport balanced"
python .\tools\audio_control.py --port COM6 --command "transport low"
python .\tools\audio_control.py --port COM6 --command "seed stats"
```

В строке P4 `transport=profile/effective` значения `0/0`, `1/1` и `0/2`
означают соответственно `BALANCED`, `LOW LATENCY` и автоматический `LOCAL`.
Поле `wire=frames/flags` показывает фактически подтверждённый Seed3 размер
блока и флаги протокола.
