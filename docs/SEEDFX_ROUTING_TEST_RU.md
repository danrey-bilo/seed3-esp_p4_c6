## Восстановление на платах

Проверен программный `seed reset` при работающем P4, LOCAL, 48 кГц:

```text
UART SEED:AUDIO_START
SeedFX graph revision=1 nodes=0 queued
UART SEED:SFX seq=2 OK
SEED:CPU ... graph=1/0 ... commits=1 rejects=0
spi=1602 err=0 frame_err[h/c/s/f]=0/0/0/0
```

До исправления первый `SEED:BOOT` мог теряться при переинициализации UART,
а после сброса Seed не получал повторный граф. Теперь P4 также повторяет
передачу по окончательному маркеру `SEED:AUDIO_START`.
Чтение графа из задачи UART ограничено числом попыток: оно не крутится
в бесконечном цикле при прерывании низкоприоритетной задачи записи.

Журналы: `.tmp/routing-final-recovery.log`, `.tmp/routing-final-stats.log`.
Граф для этой аппаратной проверки — стартовый сквозной, без эффектов.
Разветвлённые графы проверены численно на ПК, а не аналоговым измерением.

## Интерфейс на финальной прошивке P4

`ui stress`: десять проходов 0 → 12 → 0, 240 перестроений плюс восстановление
исходной схемы. Результат PASS, перезагрузок нет:

```text
board stress PASS: 10 cycles 0..12..0; original board restored; DSP unchanged
board nodes=0 heap=29868463 largest=29360128 internal=169223 stack=10604
spi=4720 err=0 frame_err[h/c/s/f]=0/0/0/0
```

Зафиксированный запас стека LVGL — 10604 байта; stack size увеличен до 16 КиБ
для вложенных операций с графом и окнами соединений. LVGL продолжает брать
heap только из PSRAM. Журнал `.tmp/routing-final-stress.log` хранится локально,
не включён в Git. Автотест временно блокирует касания и не меняет DSP-граф.

USB audio в этом прогоне не подключён (`mounted=0`), режим LOCAL передаёт
по SPI телеметрию около 50 раз/с. Проверка не заменяет USB full-duplex,
прослушивание, измерение задержки или 12 тяжёлых DSP одновременно.
