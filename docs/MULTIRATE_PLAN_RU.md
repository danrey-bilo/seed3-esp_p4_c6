# Реализация v0.2: 2x2 multirate и автоматическое восстановление

Согласовано 18.09.2026: 16/24 бита, 44,1–192 кГц; 32-битный контейнер допустим.
Сохраняем проверенный снимок `libraries/p4_uac2_stream` v0.1 без изменений.

# Граница профиля

Релиз поддерживает 44,1/48/88,2/96 кГц, 2×2 и PCM24. USB использует
3-байтный packed PCM; SPI и внутренний API — PCM24 left-aligned в `int32_t`.
У capture и playback одни физические часы Seed3; independent duplex rates и
скрытый ASRC не заявляются.

SPI mode 0 работает на 20 МГц. Wire protocol v2 использует фиксированный
DMA-кадр 544 байта, а поле `frames` выбирает 32 или 64 действительных
стереокадра. Основной `BALANCED` агрегирует два DSP-блока на 88,2/96 кГц,
`LOW LATENCY` всегда передаёт 32 кадра. Когда USB endpoint закрыты,
автоматический `LOCAL` оставляет только управляющий кадр раз в 20 мс.

Полная таблица, задержка и стендовые замеры находятся в
[TRANSPORT_MODES_RU.md](TRANSPORT_MODES_RU.md).

Релизный потолок этой версии — 96 kHz. USB не является ограничением.
Не объявляем 192 kHz и не ресемплируем скрыто 96 -> 192.

## История выбора частоты SPI

Проверен SPI 20 MHz.
96 kHz помещается; при экспериментальном 192 kHz измерено около 4300
транзакций/с вместо требуемых 6000 в прежнем 32-frame протоколе, с потерями
аудио. Ограничение — полный цикл READY/DMA/обработки, а не только число бит на
проводе. В релизе остаются 44,1/48/88,2/96 kHz и SPI 20 MHz. CRC ускорен
таблицей с тем же полиномом/результатом.

### Проверка 10 МГц в предельном режиме

18.09.2026 выполнен отдельный стендовый прогон 10 МГц при 96 кГц,
2 входах + 2 выходах и PCM24 в 32-битном транспортном слове. За 45 секунд
прошло 139 888 транзакций, темп около 2958 транзакций/с, счётчики CRC,
sequence и format errors не увеличились. Теоретически один кадр занимает
230,4 мкс из периода 333,3 мкс: провод занят на 69,12%, запас на полный
цикл READY/DMA/обработки — около 102,9 мкс.

Сравнительный замер 20 МГц на тех же данных не показал выигрыша загрузки
процессоров от перехода на 10 МГц: Seed3 — около 25,1%, SPI-задача P4 —
около 28,4–29,0% по scheduler estimate в обоих случаях. DMA, CRC и число
транзакций остаются теми же, а тактовая линия передаёт то же число бит за
секунду. Поэтому 10 МГц признаны достаточными по пропускной способности,
но не выбраны для релиза: заметной экономии вычислительной мощности нет,
а временной запас уменьшается более чем вдвое. Релиз сохраняет 20 МГц.

## Этапы

1. Seed: переключение семейства PLL3 44,1/48 kHz и SAI 1x/2x, в остановленном
   состоянии; перезапуск с пустыми rings; DMA watchdog без ручного RESET.
2. SPI: те же пакеты/CRC, расширенная проверка sample_rate; P4 передаёт
   запрошенную частоту в TX header, Seed подтверждает фактическую в RX header.
   Флаг начала новой сессии отделяет перезапуск от ошибки последовательности.
3. USB: clock GET_RANGE/GET_CUR/SET_CUR, alternate formats 16-bit и 24-in-32;
   все преобразования в task; пакетизация 44,1 kHz без потери дробной части.
   Проверить HS bInterval=3 (0,5 ms), динамические prefill/feedback/epochs.
4. ПК: выбор частоты/разрядности через стандартный UAC2; WASAPI tester
   запрашивает минимальный поддерживаемый период, показывает фактический buffer,
   не обещает общесистемный ползунок ASIO или одинаковый минимум во всех DAW.
5. Проверки: host unit tests, обе сборки/прошивки, реальное открытие форматов,
   switching/reconnect, waveform/counters, 100 open/close, 5 min duplex.
   Не объявлять непроверенные режимы прошедшими acceptance.
6. Отдельный переносимый пакет v0.2, описание API/лимитов/миграции/прошивки,
   Git cleanup, коммит и push в существующий origin без force/history rewrite.

## Автовосстановление

Seed не должен навсегда ждать completion, если P4 прервал SPI-транзакцию.
Нормальный путь остаётся completion-driven; при зависшем DMA ограниченный
watchdog выполняет программный перезапуск Seed с последующим автоматическим
согласованием частоты. Контроль BOOT/RESET доступен по существующему UART
для обслуживания, без новых проводов. Смена частоты не требует RESET.
