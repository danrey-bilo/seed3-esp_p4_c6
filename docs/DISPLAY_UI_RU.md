# Экран и телеметрия Seed3 / ESP32-P4

[← Главная](../README.md) · [Проект P4](../ESP32-P4-WIFI6-Touch-LCD-7B/README.md) · [Макет EEZ Studio](../ui/seed3_p4_ui/README_RU.md)

Текущая прошивка использует дисплей 1024×600 платы
ESP32-P4-WIFI6-Touch-LCD-7B. Дисплей запускается через BSP Waveshare 3.0.1 и
LVGL 9.5.0. Вся отрисовка выполняется отдельно от USB и SPI audio tasks.

## Окна и навигация

В прошивке есть два окна: `MONITOR` и `PEDALBOARD`. Чтобы открыть меню окон,
начните жест в верхних 80 пикселях экрана и проведите пальцем вниз минимум на
70 пикселей. Нажатие без движения меню не открывает. Нажатие карточки в уже
открытом меню переключает окно; `CLOSE` закрывает его без переключения.

Сенсор GT911 подключается по I2C и регистрируется как pointer-устройство
LVGL. Для ориентации экрана `ROTATE_0` координаты используются без `swap` и
с `mirror_x` / `mirror_y`: это соответствует физической ориентации GT911 на
плате Waveshare. Состояние и координаты опрашиваются LVGL-таймером каждые 10 мс.
Свайп распознаётся с порогом 70 px, поэтому не зависит от отключённого в этой
сборке `LV_USE_GESTURE_RECOGNITION`. Пока палец касается экрана, под ним
показывается небольшой полупрозрачный серый круг. Постоянной надписи или
кнопки навигации на рабочем поле нет.

Страница педалборда пока является макетом будущего редактора маршрутов:

- почти вся площадь отдана центральному полю для нод эффектов;
- слева находится узкий блок `IN`, справа — такой же блок `OUT`; каждый
  занимает примерно вдвое меньше площади предыдущего варианта;
- каждый блок показывает частоту и состояние каналов `CH1` / `CH2`;
- зелёный индикатор означает, что канал или блок включён, серый — выключен;
- удержание блока открывает небольшую панель с общей для `IN + OUT` частотой
  44,1 / 48 / 88,2 / 96 кГц и отдельными переключателями двух каналов;
- сверху расположен переключатель `PEDALBOARD`: без ПК он принудительно
  включён и заблокирован, с подключённым ПК доступен ручной `ON/BYPASS`;
- справа сверху постоянно отображаются процент и полоса загрузки Seed3;
- оформление плоское: без теней и анимации полос, только фон, тонкие границы и
  цвет состояния, чтобы снизить стоимость перерисовки;
- выбор частоты управляет Seed3 только в локальном режиме; при подключённом ПК
  кнопки частоты заблокированы, а экран показывает фактический общий rate;
- переключатель педалборда передаётся Seed3 по SPI и подтверждается обратно.
  DSP-ноды пока не реализованы, поэтому `BYPASS` уже является рабочим
  состоянием управления, но при пустом графе звук закономерно не меняется;
- переключатели каналов являются рабочими: маски `IN1/IN2` и `OUT1/OUT2`
  сохраняются в NVS, повторяются в каждом SPI-кадре и применяются Seed3;
- отключённый вход не проходит в USB capture и локальный тракт, отключённый
  выход получает ноль. USB-дескриптор при этом остаётся стабильным stereo 2×2.

Когда окно монитора скрыто, P4 не вычисляет peak levels. На педалборде с
интервалом 200 мс обновляется только лёгкая телеметрия CPU; USB и SPI audio при
этом продолжают работать без изменения.

## Кто управляет частотой

| Состояние USB | Педалборд | Владелец частоты |
| :--- | :--- | :--- |
| ПК не обнаружен | Принудительно `ON` | Локальный профиль P4 |
| ПК начал USB-enumeration | Начинает с `ON`, затем доступен `ON/BYPASS` | Windows |
| Capture/playback открыт | Доступен `ON/BYPASS` | Windows |
| USB SOF отсутствует и защитная пауза завершена | Автоматически `ON` | Локальный профиль P4 |

Полная логика переходов:

| Событие | Поведение |
| :--- | :--- |
| Включение без ПК | P4 загружает локальную частоту из NVS, принудительно включает педалборд и передаёт оба значения Seed3 |
| Подключение ПК | Текущая локальная частота становится начальным значением UAC2 Clock Source; с начала enumeration владельцем становится Windows |
| Кабель подключён, но приложения закрыты | Windows сохраняет владение частотой; `ON/BYPASS` доступен, локальные кнопки частоты заблокированы |
| Сон ПК, USB suspend или короткий bus reset | Состояние не переключается: сохраняются выбранная частота и режим педалборда |
| Физическое отключение | Через ≈250 мс прекращения SOF фиксируется потеря ПК, после 750-мс фильтра восстанавливаются локальная частота и принудительный `PEDALBOARD ON`; USB-контроллер готовится к повторному подключению |
| Новое подключение после отключения | Начинается новая сессия с `PEDALBOARD ON`; после enumeration снова разрешён ручной `BYPASS` |
| Windows меняет частоту при закрытых потоках | P4 передаёт запрос Seed3 и показывает `APPLYING/SYNCING` до подтверждения нового физического такта |
| Windows меняет частоту при уже открытом другом потоке | Запрос отклоняется, старый поток не перестраивается, на экране появляется `WINDOWS | CONFLICT` |
| Seed3 перезапустился | Постоянные поля каждого SPI-кадра повторно задают нужную частоту и `ON/BYPASS`; экран показывает синхронизацию до обратного подтверждения |
| Быстрые повторные нажатия switch | Очередь не накапливается: P4 применяет последнее выбранное пользователем состояние |

Локальная частота хранится в NVS и является начальным значением общего UAC2
Clock Source при следующем подключении. После начала enumeration Windows может
выбрать другую поддерживаемую частоту; экран в этот момент становится
индикатором, а кнопки 44,1/48/88,2/96 кГц — read-only. Краткий USB reset короче
750 мс не переключает режим и не дёргает аудиограф. Для self-powered P4
флаги TinyUSB `connected/mounted` могут остаться установленными после
отключения D+/D−, поэтому источником истины служит продвижение реальных SOF,
а не только эти флаги.

## Включение каналов и загрузка

Маска канала — реальная часть управления трактом, а не только цвет элемента
интерфейса. P4 передаёт две двухбитные маски в свободных управляющих битах
`status` направления P4→Seed. Размер SPI-кадра, PCM layout, CRC и sequence
control не меняются. Seed3 атомарно применяет маски между аудиоблоками:

- отключённый `IN` пропускает чтение/PCM24-конвертацию этого ADC-канала;
- отключённый `OUT` пропускает распаковку и микширование канала и выдаёт ноль;
- при четырёх отключённых каналах используется короткая ветка без
  floating-point конвертации и микширования;
- текущие маски сохраняются P4 в NVS и восстанавливаются после перезапуска.

На стенде при 48 кГц телеметрия Seed3 изменилась с примерно 13% для `3/3` до
11% для одного входа и выхода (`1/1`) и до 10% для `0/0`. Нулевая нагрузка
невозможна: аудиоклок, DMA, READY, CRC и фиксированный SPI control transport
остаются активны, чтобы канал можно было включить без перезагрузки и потери
синхронизации.

Устройство имеет один физический такт Seed3. Если второй активный endpoint
пытается изменить частоту первого, запрос отклоняется без скрытого ASRC, а на
панели появляется `WINDOWS | CONFLICT`. Смена частоты разрешена, когда оба
потока закрыты. Во время перестройки показывается `APPLYING`/`SYNCING`; новое
значение становится фактическим только после подтверждения Seed3.

## Что показывает главный экран

| Область | Значение |
| :--- | :--- |
| `SEED3 CPU` | Оценка загрузки аудиопроцессора Seed3, 0–100% |
| `INPUT / MICROPHONE` | Единая подтверждённая частота Seed3 и состояние capture endpoint |
| `OUTPUT / PLAYBACK` | Та же подтверждённая частота Seed3 и состояние playback endpoint |
| `IN 1`, `IN 2` | Peak уровни двух каналов ADC Seed3 |
| `OUT 1`, `OUT 2` | Peak уровни двух каналов USB playback |
| Нижняя строка | USB UAC2, buffer budget и счётчики SPI/CRC |

Состояние `READY` означает, что USB устройство смонтировано Windows, но
endpoint сейчас закрыт. `ACTIVE` появляется только при реально запущенном
потоке соответствующего направления. Поэтому вход и выход могут менять
состояние независимо.

## Единый источник частоты

Все окна, карточки `IN/OUT` и панель настроек читают одно поле
`sample_rate`: частоту, которую Seed3 вернул в корректном SPI-кадре. Значение
`requested_rate` не показывается как уже применённое. До первого подтверждения
вместо числа отображается `--`, а при перестройке — `APPLYING/SYNCING`.

Windows действительно хранит настройки capture и playback отдельно, поэтому
USB-компонент продолжает вести `capture_sample_rate` и
`playback_sample_rate` для журнала и диагностики. Эти поля не являются
источниками интерфейса. Seed3 имеет один физический аудиоклок, поэтому на всех
экранах одновременно может отображаться только одна фактическая частота.
Если два активных endpoint требуют разные значения, второй запрос отклоняется
и появляется `WINDOWS | CONFLICT`; скрытого ASRC нет.

## Путь телеметрии

CPU Seed3 кодируется в свободных старших битах существующего поля `status`
SPI-заголовка. Размер кадра, CRC и версия протокола не изменились. Peak levels
считаются P4 при уже выполняемой проверке PCM блока и публикуются атомарно.

Задача интерфейса работает примерно с частотой 30 Гц. В USB ISR нет LVGL,
логарифмов, выделения памяти, блокировок или пользовательских callbacks.
Это сохраняет приоритет аудиотранспорта и предсказуемую задержку.

## Проверка

После сборки и прошивки P4 выполнены отдельные exclusive-тесты:

1. capture: PCM24 stereo, 96 кГц, 192 000 кадров за 2 секунды;
2. playback: PCM24 stereo, 44,1 кГц, минимальный период Windows;
3. итоговая телеметрия: `usb=96000/44100`;
4. CRC и sequence errors SPI: 0.

Дополнительно на живом стенде проверены маски `3/3 → 1/1 → 0/0 → 3/3`:
Seed3 применяет их на следующем SPI-кадре, нагрузка меняется, SPI/CRC/sequence
errors остаются равны нулю.

Для отдельного теста выхода диагностическая программа поддерживает:

```powershell
.\tools\WasapiCapture\bin\Release\net10.0-windows\WasapiCapture.exe `
  --packed24 --rate 44100 --bits 24 --period min `
  --render-only PLAYBACK_GUID 5 exclusive
```
